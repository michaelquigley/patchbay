# 2026-10-04 — stage 1 terminus

## round 1, finding binding-1 (df-binding in the sample loader)

- Decided with Michael: no project-owned struct carries json (or dd) tags. The sample loader decodes pw-dump into bare values and walks the maps by hand. This supersedes the 2026-10-02 note that justified tagged structs with `encoding/json`.
- dd cannot take pw-dump: every dd intake decodes into `map[string]any`, and strict mode rejects a non-object root (`DecodeStrictJSON` returns "object at top level"), so a top-level array cannot be bound at all. The loader therefore uses `encoding/json` into `[]any` as the opaque-value bridge the quality allows. Do not reintroduce tagged structs to "fix" this; if dd gains array roots, the walk can move onto it unchanged.
- `UseNumber` matters: property values must render exactly as the live spa_dict would carry them ("144", not "144" via float64 formatting that would turn large serials or fractional values into exponent form).

## samples scrubbed for the public repo

`tools/capture/scrub.py` ran over `samples/` before the first commit. Rewritten consistently everywhere, including inside node and device names: the three systemd machine ids (to `0000…0001/2/3`), the Scarlett USB serials (`SCARLETT18I20`, `SCARLETT16I16`), the webcam serial (`WEBCAM`), the username and home paths (`operator`, `/home/operator`). `lsusb.txt` deleted from every sample. Hostnames and directory names kept: the spec and the fixture tests name the machines, and a hostname identifies nothing alone. The fixture counts are unchanged, since no object was removed. Future captures run through the scrub before they are copied in; the README says so. The identity logic keys on the serial string, so the placeholders are what the tests now match against, and a raw capture dropped in without the scrub would produce different keys from the same hardware.
