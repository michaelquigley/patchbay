The arc's durable lessons for the implementer, all now in the work order but easy to under-read:

- Nothing live is keyed by id. Node, client, port, and link ids all recycled within the samples, and serials can recycle across a daemon restart; reconnect clears state explicitly.
- Link provenance is a lifetime: proxy bound id plus endpoint serials plus the captured link serial, and removal before confirmation fails the request.
- Profiler pods are id-named and arrive out of order across drivers; the two clocks in each metrics record (appearance cutoff from the backend's own monotonic clock, last accepted pod clock) exist for that reason.
- scarlettctl's `Watch` always reports numid 0 and `WatchControls` swallows failed reads; the adapter refreshes everything itself.

## stage 1 — implementation

- The desktop's libpipewire 1.6.2 pkg-config cflags carry `-fno-strict-overflow`, which cgo rejects; the Makefile exports `CGO_CFLAGS_ALLOW`. Hardcoding include paths instead was considered and not done, to keep `#cgo pkg-config` as the work order decided. Whether 1.0.5 on the studio machines emits the same flag is unchecked; the export is harmless either way.
- `pw-dump.json` is decoded with `encoding/json`, not `dd`: it is a foreign capture with heterogeneous values (a top-level array, numbers and objects as property values), not configuration. `dd` stays for the workspace file.
- `sessionState` in `objects.go` (`pending`, `createdHere`, `metrics`) holds deliberately minimal types: they exist in stage 1 only so the reconnect test can prove nothing carries over. Stages 4 and 5 grow these types in place; they must stay on the per-connection `Graph` and keep being cleared by `teardown`.
- The stage 1 acceptance item "two same-key candidates delivered in separate callbacks before the sync barrier both reach the model as unassigned" is proven for the backend half only (`TestBarrierHoldsSeparateCallbacks`: nothing is published as live until both are present). The model half (no assignment on a `connecting` snapshot) lands with `internal/model` in stage 2 and needs its own test there.
- Reconnect was exercised against a private daemon, not the session one: `XDG_RUNTIME_DIR=rt pipewire` started from the scratchpad, then killed and restarted by pid. A relative runtime dir is needed because the scratchpad's absolute path exceeds the 108-byte unix socket limit. The session daemon was left alone because Michael was connected through gnome-remote-desktop, which streams through it.
- Still open for stage 1 acceptance, operator-run on the desktop: `systemctl --user restart pipewire` with `patchbay dump` running, and plugging and unplugging a USB audio device.
- Terminus has no `projects/patchbay` in the canon yet; Michael is authoring it. Stage 1's terminus rounds wait on it.
