# 2026-10-06 — placement loop, round 1

- dfx is pinned at v0.1.11, which brings `NodeFlags.Accent` and `LinkFlags.Color`. Selection now shows as a thicker line in a highlight of the block's or link's own hue (Michael's call in the dfx round), so patchbay sets no selection colors of its own.
- The media hues in `internal/ui/palette.go` are starting positions for the placement loop, not settled design: audio steel blue, midi amber, video violet, unknown neutral grey; links at 0.9 opacity.
  - They were chosen against dfx's dark default theme, mid-dark enough that the theme's white title text reads on them as a band. They have not been judged by eye.
  - If the bands read too heavy, the likely next move is a lighter link hue separate from the band hue. One hue per media was the brief.
- Glyphs: `ICON_SETTINGS_INPUT_COMPONENT` (device), `ICON_WEB_ASSET` (application), `ICON_PIANO` (MIDI bridge). The model now exposes `Block.Owner`, so the ui never parses key prefixes for this.
- The hidden-count suffix is a second `Label` on the same row after `imgui.SameLine()`, pushed to `ColTextDisabled`. That is how a single row gets two colors without dfx support; it is detent-safe because both halves are `Label`s.
- `S` snaps to dfx's canvas grid (50), not the model's placement grid (20). Fresh placements land on 20-unit positions until snapped. That's left as is; aligning the two grids is a placement-loop call.
- Fixed, from Michael's hands-on: pressing `S` right after releasing a drag snapped the block back to where the drag started.
  - Cause: dfx runs keyboard actions before the frame is drawn, so the handler read the previous frame's declarations, and that frame's `End` had just committed the move from them.
  - Same class: `C` right after a click centered on the previous selection.
  - Both now read the model's current view (`Refresh`) and the selection set, and the canvas no longer keeps last frame's declarations at all.
  - Rule: an action handler never reads a frame's plan. It reads the model and the canvas's own state, which `apply` has already updated.
