# 2026-10-05 — stage 1 acceptance and follow-up

- Stage 1 acceptance passed on `seven` (PipeWire 1.0.5): a daemon restart came back fresh with serials reused; a microKEY-25 replug came back with port id 60 reused under serial 158; `Unresolved` stayed zero throughout.
- The same run found the follow-up: the connection state flipped to `connecting` and back on every object announced after the barrier (hotplug, ordinary client arrival), with no disconnect, because `live()` demanded an empty `pendingInfo` at all times. Decided with Michael: the barrier latches (`Graph.latched`). After it, new objects never enter `pendingInfo` and never touch `ConnState`; only `lost()` and the new graph a reconnect builds go back to `connecting`. Do not reintroduce a per-object condition into `live()`.
